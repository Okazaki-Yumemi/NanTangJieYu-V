# 多货币 FX 验证记录 · 2026-11-15

本轮加入五个货币对、按货币传播的新闻、统一多品种持仓，以及持续盘整 / 趋势 / 活跃的行情模型。以下为本机短时合成测试，不是 2 核 / 2 GB 云服务器实测，也不能据此保证长期峰值容量。

环境：Windows 11，Node.js v24.15.0，AMD Ryzen 9 9955HX，32 个逻辑处理器，系统内存 31.2 GiB。服务与负载发生器分进程运行，使用独立测试目录，仅监听回环地址；两轮顺序执行，结束后均关闭服务。正式存档没有参与测试。

## 正确性与界面

- 全套 `npm test`：182 项通过，0 失败。
- 后续审计价格归属修正后，相关领域与 HTTP 接口回归 9 项全部通过。
- 新增覆盖：旧持仓迁移且不改变资金 / 请求回执、五品种多空和人里元统一结算、跨品种重复请求拒绝、过时报价拒绝、目标货币新闻 / 跨盘换算 / 独立强平、多品种审计与重启持久化。
- 固定种子的 6,000 拍检查：价格有限且在区间内，交叉盘始终等于两条直接汇率之比；三种走势状态均出现，相关方向符合设定且未长期卡在边界。此测试验证模型行为，不是现实市场校准。
- 实际浏览器检查：五种行情切换、2 秒蜡烛、六位小数交叉盘开仓、查看交叉盘时平掉月都持仓、后台月都事件、五品种审计。浏览器没有脚本错误；桌面与 390 px 手机视口均检查，手机整页没有水平溢出，报价栏可单独横向滑动。

## 较重的 FX 存档

命令：`node scripts/benchmark-backend.js --users 150 --seconds 15 --writes fx`

150 个账户各有 12 笔持仓、30 笔结算，分布在五个品种；每个市场都填满 180 拍报价、180 根 2 秒蜡烛和 360 根 10 秒蜡烛。行情固定，用来检查较大快照的读写开销；先同时平仓 150 笔，再持续 15 秒发送 100 次/秒查询和 15 次/秒交易。每个 FX 响应只包含选定品种的完整图表。

| 指标 | 结果 |
| --- | ---: |
| 总请求 | 1,875 |
| HTTP 错误 | 0 |
| 查询 p95 / p99 | 39 / 63 ms |
| 持续交易 p95 / p99 | 627 / 1,089 ms |
| 150 笔同时平仓全部完成 | 3,124 ms |
| 结束采样 RSS（非峰值） | 370 MiB |
| 单核等效 CPU | 86% |
| 实际响应体 | 11.45 MB |

集中写入仍有排队成本；全状态 JSON 持久化依旧是主要容量约束。该轮固定行情，不覆盖排队期间真实换拍导致的过时报价，后者由正确性测试和下面的实时混合负载覆盖。旧报告只有单品种历史，不能将这些数值直接当作同数据量对照。

## 150 人全站混合游玩

两条命令在不同终端执行，目录应使用尚未存在的新路径：

```powershell
node scripts/benchmark-mixed.js --server --dir .scratch/fx-multipair-check --port 3148
node scripts/benchmark-mixed.js --dir .scratch/fx-multipair-check --port 3148 --seconds 30
# 读取 report.json 后关闭测试专用服务
Invoke-RestMethod http://127.0.0.1:3148/__loadtest/stop
```

分布为 FX 40 人（五品种各 8 人）、校园互动 35 人、钓鱼 25 人、弹幕 20 人、推箱子 15 人、染色 15 人。包含注册、登录、30 秒实时游玩、150 人集中提交成绩、最终账户与落盘检查，共 3,402 个请求，错误及业务拒绝均为 0。

| 混合阶段操作 | 请求数 | p95 |
| --- | ---: | ---: |
| FX 查询 | 600 | 3.54 ms |
| FX 交易 | 150 | 25.53 ms |
| 校园查询 / 互动 | 175 / 70 | 3.50 / 24.07 ms |
| 钓鱼查询 / 结算 | 375 / 25 | 2.08 / 15.70 ms |
| 弹幕 / 推箱 / 染色提交成绩 | 20 / 15 / 15 | 17.03 / 15.72 / 19.47 ms |
| 额外 150 人集中提交成绩 | 150 | 450.13 ms |

服务进程全程原生峰值 RSS 为 219.91 MiB；30 秒混合游玩阶段采样峰值 146.56 MiB，单核等效 CPU 17.02%。这是新建的较小存档：最终约 421 KiB，不能替代满历史存档或长时间运行验证。

这是 HTTP 虚拟用户测试，未启动 150 个图形浏览器；钓鱼使用实际计时和控制回放，其余客户端游戏提交合法的模拟结果，不包含外部猜图网站。部署仍需单实例写入、持久化 SSD，并在目标机器上复测。
