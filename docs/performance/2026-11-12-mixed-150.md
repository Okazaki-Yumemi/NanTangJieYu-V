# 150 用户全站混合负载测试

测试时间：2026-11-12 18:42～18:45（Asia/Shanghai），随后验证停服重启。项目完整启动，使用独立测试数据目录，没有修改正式账号或运行数据。

## 结论

当前工作区的 158 项自动化测试全部通过。150 个 HTTP 虚拟用户按不同玩法持续活动 180 秒，期间完成 **9,600 次业务请求，0 次失败、0 次业务拒绝**。加上冷资源加载、集中注册/登录、开通 FX 和集中上榜，共完成 **11,308 次业务请求**；重启后又验证了 150 个账号登录成功。

服务进程在整个负载期间的操作系统记录内存峰值为 **269.95 MiB**。这组负载支持将专用 2GB 机器作为公测起点，但不是目标云服务器的承载保证。

## 测试环境与边界

- 代码基线：`d4ba248`，包含工作区此前未提交的弹幕玩法、控制和相关接口改动；未把这些改动当作已发布版本。
- Windows 11 / Node.js v24.15.0；宿主 AMD Ryzen 9 9955HX，32 个逻辑处理器、31.2GiB 内存。
- **仅服务进程**绑定到 2 个逻辑处理器，ProcessorAffinity = 3；V8 旧生代上限 768MiB。没有把整个操作系统限制为 2GiB，也不能等同于某款云端 2 vCPU。
- 客户端与服务进程分开，本机 HTTP 回环，未模拟公网延迟、TLS 或套餐带宽上限。
- 是 150 个有独立账号和会话的 HTTP 虚拟用户，不是同时运行 150 个图形浏览器。弹幕、推箱、染布使用合法模拟成绩上报和榜单查询；校园任务提交实际结算接口。钓鱼使用共享游戏引擎生成控制轨迹，等待对应游戏时长后交给服务器回放校验。
- 冷加载覆盖各玩法 HTML 直接引用的 JS、CSS、图片，不包含浏览器执行后才出现的所有动态资源。外链「幻想图寻」由第三方承载，未对第三方进行压测。

操作节奏：FX 每 2 秒查询、约每 8～10 秒交易；校园每 6 秒刷新，至少间隔 20 秒且能量足够才提交任务；钓鱼每 2 秒查状态，遵守 30 秒冷却和实际回放时长；其余小游戏每 10 秒查榜、约 30～40 秒提交一次成绩。

- 持续阶段平均吞吐约 **53.3 次请求/秒**。
- 持续阶段 CPU 平均使用约 **0.138 个逻辑核心**，相当于两个指定逻辑处理器总算力的约 **6.9%**；这是进程 CPU 时间的平均值，不是峰值。
- 持续阶段 200ms 采样的 RSS 峰值 **238.36MiB**；全测试系统记录的 RSS 峰值 **269.95MiB**。
- 持续阶段压缩响应体共 **25.179MB**，平均约 **1.12Mbps**，不含请求、协议头和 TLS。
- 任务结束后写队列为 0，未出现写入阻断。突发阶段最多同时等待 149 个事务，随后排空。

## 复现方式

在一个终端启动独立测试服务：

```bash
node --max-old-space-size=768 scripts/benchmark-mixed.js --server --dir .scratch/mixed150-demo
```

另一个终端运行负载：

```bash
node scripts/benchmark-mixed.js --dir .scratch/mixed150-demo --seconds 180
```

默认只监听 `127.0.0.1:3147`。使用全新的测试目录；运行第二次前应选择新目录，避免账号重名或活动已经开始。脚本本身不设置 CPU 亲和性；本次是在 Windows 启动服务后将该服务进程的 `ProcessorAffinity` 设置为 3。

测试服务带有仅用于回环测试的 `/__loadtest/` 观测接口，不要将这个测试启动器作为公网生产启动命令。测试完成后服务保留，调用 `/__loadtest/stop` 可关闭该测试实例。生产环境仍使用 `npm start`。

本次原始结果：工作区 `.scratch/mixed150-20261112-184151/report.json`；每秒采样记录：同目录 `samples.jsonl`；自动化测试日志：`.scratch/test-150-full-suite.log`。
