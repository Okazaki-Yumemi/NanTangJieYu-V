# 后端并发与压测

当前后端面向约 150 人的活动场景，仍采用单实例 Node.js 和 JSON 持久化，无新增第三方依赖。旧 `data/state.json`、账号、注册码、持仓均可直接加载，无需迁移或清空。

## 已完成的优化

- **存储**：启动时加载已提交快照，写事务不再重复读盘；只复制工作草稿，取消或抛错时丢弃。等待中的事务按顺序分成最多 16 个一批，合并主备文件写入。每批只序列化新状态一次，复用上一批的序列化结果生成备份，并移除 JSON 缩进。
- **确认时机**：主备文件完成 `fsync` 和原子替换后才更新可读快照、返回成功。同批事务看到前序成功事务的结果，外部查询只能看到整批提交前或提交后的状态。独立管理快照作为批次屏障处理。主文件损坏时仍可回退到上一批备份。
- **查询**：FX、钓鱼、游园会、总贡献和区域榜单按已提交快照缓存，写入后立即失效。可变草稿不参与缓存，避免算出过期榜单。FX 和校园互动的响应视图移到提交后构建。
- **密码**：HTTP 注册、登录通过异步 `scrypt` 计算，最多同时执行两个密码任务；注册码、昵称、封禁和密码版本在写事务中重新校验。命令行/领域测试仍保留同步接口。
- **网络**：大于等于 1KB 的 JSON 在客户端允许时异步 gzip，遵守 `gzip;q=0`；静态文件使用异步 `stat`、ETag/304 和 HEAD。响应仍按各接口原有权限构建。
- **过载和关闭**：待处理写事务上限 512，超限的玩家请求返回 503 和 `Retry-After`。落盘失败时拒绝后续写入，健康检查返回 503，重启时走主备恢复。正常 SIGTERM/SIGINT 先停止接入并等待在途事务。

## 本机对照结果

2026-11-12，Windows / Node.js v24.15.0，同一台机器，服务端与压测客户端分进程。旧版基线为 `d375f42`，新版为本次优化工作区。

合成 150 个账号，每个 FX 账户初始有 12 笔持仓、30 笔平仓记录；先并发提交 150 次 FX 平仓，再持续 12 秒发送每秒 75 次 FX 查询、25 次校园主页查询和 15 次 FX 平仓。合计 1,200 次查询、330 次交易。两次均完成全部请求且 HTTP 错误为 0。

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 150 次同时平仓的总耗时 | 13,780 ms | 1,929 ms |
| 持续阶段查询 p95 | 3,701 ms | 22 ms |
| 持续阶段交易 p95 | 5,028 ms | 52 ms |
| 持续阶段交易 p99 | 5,172 ms | 86 ms |
| 12 秒发出的请求全部完成所需时间 | 17,217 ms | 12,042 ms |
| 全程响应体传输量 | 26.82 MB | 4.57 MB |
| 服务进程结束采样 RSS | 300 MB | 253 MB |

这里的 p95 表示 95% 的请求在该时间内完成。传输量统计实际网络响应体，未包含 HTTP/TLS 头；压缩前后逻辑内容一致。该结果是本机短时合成负载，不等于某款 2 核云服务器的承载保证，也没有包含跨网延迟、图片首屏和集中登录负载。需在目标机器上复测。

## 复现

```bash
# FX 读写，默认 150 人 / 15 秒
npm run bench:backend -- --users 150 --seconds 15 --writes fx

# 同一负载，写入改为游园会成绩
npm run bench:backend -- --users 150 --seconds 15 --writes arcade

# 对照其他已经检出的版本（代码目录必须包含 tests/helpers/fixture.js）
node scripts/benchmark-backend.js --root /path/to/old-checkout --seconds 12 --writes fx
```

脚本只创建临时目录，明确传入临时 `dataDir`，只监听 `127.0.0.1` 的随机端口，完成后关闭子服务并删除该临时目录；不会使用正式 `DATA_DIR`。不要同时运行两个性能测试，以免互相争抢资源。FX 场景只能关闭初始持仓，持续阶段交易总数不得超过 `人数 × 11`。

## 部署边界

- 同一个数据目录仍只能有 **一个写进程**。不要开启 PM2 cluster、多个副本或滚动重叠运行。内存快照不会监视外部文件修改；生成码、开发数据等写脚本必须停服执行。服务在线时使用管理接口。
- `/data` 必须使用持久化 SSD 卷。共享/远程盘的 `fsync` 延迟会影响结果。`state.json.bak` 为上一批快照，不能代替独立异地备份。
- 交易页面收到网络错误时，应使用原请求 ID 重试；已有 FX 幂等逻辑保持不变。503 仅表示请求未被写队列接收，不能无限并发重试。
- 若未来需要多实例或更高写入吞吐，应迁移到支持事务的共享数据库；本次优化没有把 JSON 文件改造成分布式数据库。

实现依据：[Node.js 异步密码计算](https://nodejs.org/api/crypto.html#cryptoscryptpassword-salt-keylen-options-callback)、[压缩与线程池](https://nodejs.org/api/zlib.html#threadpool-usage-and-performance-considerations)、[文件同步](https://nodejs.org/api/fs.html#filehandlesync)。
