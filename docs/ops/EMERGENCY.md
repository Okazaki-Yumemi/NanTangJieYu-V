# 现场应急手册（EMERGENCY）

> 配套《[EVENT_RUNBOOK.md](EVENT_RUNBOOK.md)》使用。每条按「症状 → 30 秒判断 → 处置 → 事后」组织。
>
> **总原则（先读这三条）：**
> 1. **先分辨「坏了」还是「本来就这样」**：玩家端大量提示都能在手册附录 B 查到含义（体力用完、区域未解锁、活动暂停），这些不是故障。
> 2. **任何情况下不要删除/重建 `data/` 目录来"让服务能启动"**。状态文件损坏时系统会自动从备份恢复；两边都坏会拒绝启动，此时走第 4 节恢复流程。
> 3. 所有写操作逐笔原子落盘，**进程崩了不丢已确认的数据**；重启后玩家登录态也在（不要求重新注册/登录）。

---

## 1. 服务挂掉 / 进程退出

**症状**：玩家全部提示网络错误；服务器上没有 node 进程；`/healthz` 打不开。

**30 秒判断**：到服务器上看启动终端是否还在、报了什么错。

**处置**：
1. 重新启动：`node server/index.js`。
2. 走一遍启动自检 5 项（手册 1.3）：healthz、玩家页、管理入口、登录后刷新、数据目录。
3. 通知现场：玩家刷新页面即可继续，进度不丢。

**事后**：把崩溃前的终端报错抄下来发给开发。**建议活动全程不要把启动终端最小化到看不见**，崩溃原因就打在那里。

---

## 2. 页面打不开（玩家端 / 管理后台）

**症状**：浏览器转圈/超时，或「无法访问此网站」。

**30 秒判断**：在服务器本机开 `http://127.0.0.1:3000/healthz`。

| 本机结果 | 结论 | 去哪 |
| --- | --- | --- |
| ok | 服务正常，问题在链路 | 看下面「链路三查」 |
| 打不开 | 服务/端口问题 | 回第 1 节 |

**链路三查**（本机 ok 但别的设备不通）：
1. 手机和服务器是否同一 Wi-Fi/网段（访客网络隔离是头号原因）。
2. 用**IP** 访问而不是 `localhost`（现场公布的地址应该是 `http://<服务器IP>:3000`）。
3. Windows 防火墙：首次启动 Node 的弹窗如果被点了「取消」，后续会一直拦。控制面板 → 防火墙 → 允许应用通过防火墙 → 勾选 Node.js（专用+公用）。

**服务正常但接口全 500**：看磁盘是否写满（状态文件每笔操作都要落盘）。清理磁盘后自动恢复。

---

## 3. 网络断 / 局域网抖动

**症状**：个别玩家提示「网络连接失败，请检查网络后重试。」；大屏偶发停更。

**先知道的机制**（已实测验证）：
- 玩家端请求失败会弹提示、按钮恢复可点，**不会出现假成功**；网络恢复后重试即可。
- 每次行动带唯一请求标识，服务端幂等：**就算请求到了服务器、响应在半路丢了，玩家重试拿到的还是第一次的结果，不会重复计分**。所以「我点了没反应，再点会不会扣两次」的答案是不会。

**处置**：让玩家重试/刷新；成片断网查交换机/AP。玩家坚持说扣了没到账 → 「玩家管理」搜人 → 看贡献流水，没有那条就正常，有那条让他刷新。

## 4. 状态文件损坏

**症状分级**：

| 现象 | 含义 | 处置 |
| --- | --- | --- |
| 启动日志出现 `Recovering ... from ...` | 主文件坏，**已自动**从 `state.json.bak` 恢复 | 无需操作，确认数据正常即可，最多丢最后一笔操作 |
| 启动直接失败，报 `State recovery failed` | 主文件和备份**都**读不了 | 按下面流程走，**不要删 data 目录** |

**恢复流程（双损坏）**：
1. 停服务。
2. 找最近的外部备份（手册 7.2 做过的 U 盘/网盘拷贝），把其中的 `state.json` **和 `state.json.bak` 一起**放回数据目录。
3. 数据目录里若有 `state.*.json` 独立快照（危险操作前自动落），也可用作恢复源。
4. 启动服务，自检 5 项。

**事后**：把两个损坏文件原样保留拷走发给开发，不要覆盖。

## 5. 管理员登录失败

| 症状 | 原因 | 处置 |
| --- | --- | --- |
| 提示「口令错误。」 | 密码错 | 核对 `.env` 的 `ADMIN_PASSWORD`；注意是**活动当天新设的那个**，不是演示口令 |
| 提示「尝试过于频繁」 | 10 分钟内错满 20 次（按 IP 计） | 等 10 分钟，或重启服务立即清零（仅影响登录限流，不影响数据） |
| 登录成功但一刷新就退回登录页 | Cookie 被 `COOKIE_SECURE` 丢弃（http 部署 + production 配置的坑） | `.env` 加 `COOKIE_SECURE=0`，重启，重登 |
| 提示「请先登录。」 | 8 小时无操作，会话过期 | 重新登录 |
| `.env` 里根本没设口令 | 随机口令只在启动日志打印一次 | 重启服务，从日志抄新口令；**顺手把 ADMIN_PASSWORD 写进 .env** |

注意：重启**不会**把已有管理会话踢掉（会话存在数据里）。若怀疑后台被无关人员登录过：重启服务并换 `ADMIN_PASSWORD`，再让所有后台窗口重新登录。

## 6. 玩家重复操作 / 贡献争议

**典型诉求**：「我做了没加分」「加多了」「我俩用一个号」。

**机制**（先讲给玩家听）：
- 每次行动带唯一标识，服务端按标识幂等——重复提交/断网重试都只算一次，重复加分在机制上不成立。
- 所有加分（含管理员手动调整）都有流水，可按玩家、区域、类型过滤查询。

**处置**：
1. 后台「玩家管理」搜到玩家，看贡献流水：有没有那笔、时间对不对。
2. 流水里没有而玩家确实操作过（比如断网那一刻）→ 让他重试一次即可，不会双计。
3. 确需补偿/更正 → 「调整贡献」，**必填事由**（写「断网补偿 09:42」这种可对账的），流水与操作日志双留痕。
4. 「我俩用一个号」→ 各自重新注册（各用各的码），老号走「强制下线」；想合并贡献用「调整贡献」人工搬。
5. 玩家点了「结束活动」后的互动 → 已结束状态下行动被拒是预期行为，不是丢数据。

## 7. 大屏失效

**症状**：大屏画面停住/内容过期。

**机制**：大屏每 3 秒自动拉取，纯展示、不需要登录。

**处置**（按顺序）：
1. 大屏机上按 F5 刷新（解决 99% 的「画面停住」——投影机浏览器长时间运行后的假死）。
2. 刷新后白屏 → 关掉重开 `http://<服务器IP>:3000/display.html`。
3. 别的设备正常、只有大屏机不正常 → 大屏机自身网络/浏览器问题，重启浏览器。
4. 全部端都不更新 → 回第 1/2 节查服务。
5. 大屏机浏览器彻底卡死 → 任务管理器结束进程重开。**建议活动全程大屏浏览器保持全屏模式（F11），减少误触。**

## 8. 抽奖异常

| 症状 | 30 秒判断 | 处置 |
| --- | --- | --- |
| 点了「抽取」没反应/报错 | 看报错文案 | 「奖品尚未解锁」→ 对应区域没解决，先推进区域或用「强制解决当前区域」；「该奖品已被抽完」→ 换奖品；「当前没有可参与的玩家」→ 池子空（都中过了或没人），检查 prevent 规则 |
| 中奖人不在场 | — | 「作废重抽」。作废不占奖品份数、不记为中奖，放心操作 |
| 玩家质疑重复中奖 | 后台抽奖记录逐条可查（含权重快照、池子大小） | 同一奖品每人最多一次是服务端强制的，不存在重复；「作废重抽」的记录会标「已作废」 |
| 抽奖台动画卡住 | 看是否已出结果 | 已出结果就直接走确认/作废流程，动画只是展示；没出结果就刷新页面重抽（抽奖是单次原子操作，刷新不会产生两次抽取） |
| 误抽了不该抽的奖品 | — | 该记录「作废重抽」，作废原因会留痕 |

**抽奖前防呆两件套**：确认奖品份数剩余；确认「作废重抽」的测试记录已清理（手册 2.5 的彩排记录）。
