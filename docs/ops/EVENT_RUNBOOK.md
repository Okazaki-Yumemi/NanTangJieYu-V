# 活动日现场手册（EVENT_RUNBOOK）

> 读者：活动当天操作管理后台的人（不要求了解代码）。
> 用法：按时间线走；出事翻《[EMERGENCY.md](EMERGENCY.md)》。
> 所有按钮名、页面名、提示文案均与当前版本管理后台逐字一致，已按 2026-09 代码核实。

---

## 0. 时间线速览

| 时段 | 你要做什么 | 在哪里做 |
| --- | --- | --- |
| 开场前 1 小时 | 启动服务 → 开机自检 → 生成注册码 → 导出 CSV 备份 | 服务器 + 后台「注册码」页 |
| 开场前 30 分钟 | 确认注册开放 → 三端各开一遍验货 → 抽奖台彩排一次 | 后台全部页签 |
| 活动开始 | 「开始活动」 | 「活动状态」页 |
| 进行中 | 盯在线人数/区域进度；处理玩家请求；按节目推进区域 | 「活动状态」「地图区域」「玩家管理」页 |
| 现场抽奖 | 抽取 → 确认有效 → 标记领取（不在场就作废重抽） | 「抽奖」页 |
| 结束 | 「结束活动」（不可逆）→ 导出 → 备份 | 「活动状态」页 + 服务器 |

## 1. 启动服务与开机自检

### 1.1 配置（`.env`，在项目根目录，改动后需重启生效）

```ini
# 活动日推荐配置
PORT=3000
ADMIN_PASSWORD=<现场口令，活动当天新设，不要用演示口令>
ADMIN_ENTRY_PATH=<随机路径，如 /ntjv-admin-7k3x.html>
NODE_ENV=development
COOKIE_SECURE=0
```

两条硬规矩：

1. **现场走 `http://局域网IP:3000` 时必须 `COOKIE_SECURE=0`**。若设了 `NODE_ENV=production` 而没显式关掉它，服务会把登录 Cookie 标记为「仅 HTTPS」，浏览器直接丢弃——症状是「登录成功，一刷新就退回登录页」。现场没有 HTTPS，所以要么保持 `NODE_ENV=development`，要么 `production` + `COOKIE_SECURE=0` 成对出现。
2. `ADMIN_PASSWORD` 不设也能启动，但口令是**随机生成、只打印一次在启动日志里、重启就换**。现场不要用这种模式。

改完 `.env` 必须重启服务才生效（规则种子 `shared/seeds/*.json` 同理）。

### 1.2 启动

```bash
node server/index.js
```

启动成功日志固定三行：服务地址、管理员入口地址、数据目录。**把这三行拍下来或抄下来。**

> Windows 上启动时会先打出两条 `Could not fsync state directory ... EPERM` 警告——这是 Windows 对目录 fsync 的限制，服务已改为忽略，属预期噪音，不算失败（已实测确认）。

### 1.3 开机自检（5 项，全过才算就绪）

| # | 检查 | 做法 | 不过意味着 |
| --- | --- | --- | --- |
| 1 | 服务活着 | 浏览器开 `http://<本机IP>:3000/healthz`，见 `{"status":"ok"...}` | 进程没起/端口被占 |
| 2 | 玩家端能开 | 开 `http://<本机IP>:3000/`，见注册页 | 静态资源问题 |
| 3 | 管理入口能开 | 开 `.env` 里配的管理入口路径 | `ADMIN_ENTRY_PATH` 打错 |
| 4 | 管理员能登录且**刷新后仍在登录态** | 输入口令登录 → 按 F5 → 还在后台 | Cookie 被丢弃，回查 1.1 第 1 条 |
| 5 | 数据目录正确 | 启动日志第三行的 `data` 目录是本次活动要用的那个 | `DATA_DIR` 指错，写到别的活动存档上 |

局域网其他设备（手机）连不上时：先确认手机和服务器在同一网段，再确认 Windows 防火墙放行了该端口（首次启动 Node 时弹窗要点「允许」）。

## 2. 开场前（PRE-EVENT）

### 2.1 生成注册码（必须，新数据目录里一个码都没有）

「注册码」页 → 「批量生成注册码」：填数量、类型（普通/稀有等，影响初始抽奖权重）、备注（写「现场-上午场」这类批次用途）→ 「生成」。
生成后页面列出全部新码，每个码可点开**二维码地址**（玩家扫码直达注册页，注意把地址里的域名换成现场公布地址）。

**生成后立刻点「导出 CSV」**，把文件存到 U 盘/网盘。这是注册码的唯一外部备份——玩家弄丢码时靠它查。

### 2.2 确认注册开放

「活动状态」页看注册开关：显示可点「关闭注册」即当前已开放（注册开关独立于活动状态，没开始活动也能先注册）。
想先压着不让人进：点「开放注册」按钮是灰的、旁边「关闭注册」可点，即为已关闭状态。

### 2.3 玩家注册流程（帮玩家前先自己走一遍）

玩家页 → 输入**注册码 + 昵称（1–16 字符）+ 密码（至少 4 位）+ 选阵营**（灵梦/魔理沙，双方人数差超 15 人会被拦，选人少的那边）。

### 2.4 三端验货

| 端 | 地址 | 看什么 |
| --- | --- | --- |
| 玩家端 | `/` | 注册、进大厅、地图能点开区域 |
| 大屏 | `/display.html` | 未开始状态的标题/阵营展示正常 |
| 后台 | 管理入口 | 各页签能打开，「操作日志」页有本次自检留痕 |

### 2.5 抽奖台彩排（两分钟）

「抽奖」页任选一个「基础」奖品抽一次 → 「作废重抽」（作废不占奖品份数，也不影响玩家）→ 确认抽奖台动画和大屏联动正常。正式抽之前把测试记录作废掉即可。

## 3. 活动进行中（EVENT）

### 3.1 状态流转

「活动状态」页：**开始活动**（只能从「未开始」按一次）→ 进行中。此后：

- **暂停活动**：临时停场（赛道解说、突发状况）用这个。暂停期间玩家行动会被拒（提示「当前活动未在进行中」），恢复后一切照旧。
- **继续活动**：从暂停回来。
- **结束活动**：不可逆。按钮是红色实心，有二次确认（「结束后玩家无法继续互动与获取贡献」）。**确定不再恢复才按。**

### 3.2 注册开关

人满/中场可「关闭注册」，不影响已注册玩家。「开放注册」随时可再开。

### 3.3 盯什么

- 「活动状态」页：在线/注册人数、双方阵营贡献对比、当前阶段区域进度。
- 「操作日志」页：所有后台操作都有留痕，争议时先来这里对时间线。
- 玩家反馈「打不动了」→ 多半是体力耗尽（上限 5 点，每 45 秒回 1 点）或区域已解决，不是故障。见 5.1。

### 3.4 推进剧情（现场节目用）

「活动状态」页的**「强制解决当前区域」**按钮：按固定顺序（思源门 → 思源湖 → 凯旋门 → 电草 → 涵泽湖 → 行政楼）找到第一个未解决区域，直接判解决，同时**注入该区域对应奖品、解锁下一区域**，玩家端和大屏会收到系统播报。二次确认弹窗会写明将解决哪个区域。

区域进度正常由玩家贡献推进；这个按钮只用于节目节奏控制（例如互动人数少、赶流程）。

### 3.5 单区域应急

「地图区域」页每个区域有四钮：

| 按钮 | 用途 | 注意 |
| --- | --- | --- |
| 强制解锁 | 区域处于锁定态但节目需要立刻可打 | 只对锁定区域可点 |
| 强制解决 | 判该区域已解决（异变清零，系统播报「管理员强制解决」） | 解锁对应奖品 |
| 关闭 / 重开 | 临时封闭某区域（故障、太挤） | 关闭期间玩家在此行动被拒 |

⚠️ 不要手动把已解决区域的异变值改回大于 0——那会把它**重新变回未解决**，可能触发重复解锁/重复结算。确需回退区域，先想清楚再操作，并记下操作时间。

## 4. 玩家管理（每项一句话）

「玩家管理」页搜索玩家后可执行（危险项均有二次确认）：

| 操作 | 什么时候用 |
| --- | --- |
| 强制下线 | 玩家账号疑似被旁人共用/手机借给他人后踢会话 |
| 封禁 / 解封 | 明确捣乱（刷屏、恶意昵称）才封；封禁玩家无法登录且不进抽奖池 |
| 重置密码 | 玩家忘密码（现场直接给新密码） |
| 恢复体力 | 体力显示异常或活动刚开始想让大家满血 |
| 调整贡献 | 补偿（断网漏计、误操作）；**必须填事由**，会进贡献流水和操作日志 |
| 重命名 | 昵称违规 |
| 更换阵营 | 双方严重失衡或玩家强烈要求；其个人贡献会随人走，操作前后都留痕 |
| 换绑注册码 | 玩家换了码（重注册场景），旧码释放 |
| 设置抽奖权重调整量 | 几乎不用；范围 −100~100，只影响该玩家抽奖权重 |

查账：「贡献流水」按玩家/区域/类型过滤；怀疑漏计先看流水里有没有那条记录，再找操作日志对时间。

## 5. 现场抽奖

### 5.1 前置条件（抽不出来时对照）

1. 奖品已解锁：「基础」奖品始终可抽；带区域来源的奖品要对应区域已解决（「强制解决当前区域」会自动解锁）。
2. 奖品有剩余份数。
3. 池子里有合格玩家：被封禁的不进池、已中过该奖品的不进池、权重为 0 的不进池。

### 5.2 仪式流程

「抽奖」页 → 选奖品 → 点抽取 → 抽奖台滚动 → 出结果（大屏同步）：

1. **确认有效**：中奖人在现场、确认领奖意愿后点。
2. **标记领取**：实际发奖时点。
3. **作废重抽**：中奖人不在场/弃权。作废不占奖品份数、不记为该玩家中奖。

规则一句话（页面下方也写着）：同一玩家可中多个**不同**奖品，同一奖品每人最多一次。

### 5.3 争议处理

每条抽奖记录都带**权重快照、池子大小、总权重**。玩家质疑公平性时：抽奖记录页展示这些数字，可以当场解释「按贡献累计的权重抽取，全程留痕」。对结果有争议的记录走「作废重抽」，不要手动改数据。

## 6. 收尾（POST-EVENT）

1. 「结束活动」（不可逆，确认全场节目已完成）。
2. 「注册码」页「导出 CSV」终版留档。
3. **备份**：见第 7 节，结束时必做一次。
4. 数据目录整体拷贝归档（含 `ledger.jsonl` 贡献审计、抽奖记录、操作日志）。

## 7. 备份与恢复

### 7.1 数据目录里有什么

| 文件 | 是什么 |
| --- | --- |
| `state.json` | 全部运行状态（玩家/区域/抽奖/会话/日志），每次写操作原子替换 |
| `state.json.bak` | 上一笔事务的快照，主文件损坏时自动恢复源 |
| `ledger.jsonl` | 贡献流水审计，追加式 |
| `state.*.json` | 危险操作前的独立快照（留档用） |

### 7.2 做备份（活动当天至少：开场前一次、抽奖前一次、结束时一次）

1. 「暂停活动」（避免备份瞬间有写入，虽然原子写保证拷到的都是完整状态，但流水可能正写一半）。
2. 复制**整个数据目录**到 U 盘/网盘。
3. 「继续活动」。

### 7.3 恢复到某份备份

1. 停掉服务（关进程）。
2. 用备份里的 `state.json` **和 `state.json.bak` 一起**覆盖现文件——只放主文件的话，旁边旧的 `.bak` 会在未来某次损坏时把状态拉回更早的时点。
3. 启动服务，自检 5 项过一遍。

## 附录 A：管理 API 速查（后台页面打不开时 curl 直连）

所有请求需先登录拿 Cookie；写操作均留管理日志。

```bash
BASE=http://127.0.0.1:3000
# 登录（-c 存 Cookie）
curl -c admin.jar -X POST $BASE/api/admin/login -H "Content-Type: application/json" -d '{"password":"<口令>"}'
# 之后每个请求带 -b admin.jar

# 活动操作
curl -b admin.jar -X POST $BASE/api/admin/activity -d '{"action":"start"}'        # start|pause|resume|end|open_registration|close_registration|advance_stage
# 区域操作
curl -b admin.jar -X POST $BASE/api/admin/region -d '{"region_id":"siyuan_gate","op":"force_clear"}'  # set_anomaly(带value)|force_clear|force_unlock|close|reopen
# 玩家操作
curl -b admin.jar -X POST $BASE/api/admin/player -d '{"user_id":"<id>","op":"restore_energy"}'        # ban|unban|reset_password(带password)|restore_energy|force_logout|adjust_contribution(带amount,reason)|rename|switch_team|rebind_code|set_weight_override(带value)
# 注册码
curl -b admin.jar -X POST $BASE/api/admin/codes/generate -d '{"count":30,"type":"normal","note":"现场"}'
curl -b admin.jar -X POST $BASE/api/admin/codes/disable -d '{"code":"<码>","disabled":true}'
curl -b admin.jar "$BASE/api/admin/codes/export" -o codes.csv                        # CSV 含 BOM，Excel 直开
# 抽奖
curl -b admin.jar -X POST $BASE/api/admin/lottery/draw  -d '{"prize_id":"<奖品id>"}'
curl -b admin.jar -X POST $BASE/api/admin/lottery/record -d '{"op":"claim","draw_id":"<记录id>"}'     # confirm|claim|void(带reason)
# 查询
curl -b admin.jar "$BASE/api/admin/bootstrap"                                        # 全量后台状态
curl -b admin.jar "$BASE/api/admin/ledger?limit=50"                                  # 贡献流水
```

## 附录 B：玩家端错误提示 → 现场解读

| 玩家看到的报错 | 含义 | 现场说法 |
| --- | --- | --- |
| 当前活动未在进行中。 | 活动未开始/已暂停/已结束 | 「等主持人宣布开始」 |
| 当前暂未开放互动。 | 活动在进行但互动被单独关了 | 找管理员确认开关 |
| 请先注册或登录。 | 会话失效（12 小时无操作/被强制下线/换设备） | 重新登录即可，贡献都在 |
| 「××」尚未解锁。 | 前置区域未解决 | 「先推进前面的区域」 |
| 「××」暂时关闭，请稍后再来。 | 区域被管理员临时关闭 | 找管理员确认 |
| 「××」的异变已经解决！ | 区域已 CLEAR | 「去下一个区域」 |
| 能量不足，请等待能量恢复或选择其他互动。 | 能量（5 点上限）用完 | 「每 45 秒回 1 点，歇一会」 |
| 「××」冷却中，还需 N 秒。 | 该互动在冷却 | 等倒计时 |
| 操作太频繁了，请稍候再试。 | 400ms 内连续点击 | 「点一下等一下」 |
| 注册码不存在，请检查是否输入正确。 | 码打错 | 核对纸质码 |
| 这个注册码已经被使用。 | 码已被绑定 | 后台「注册码」页查绑定人 |
| 这个注册码已被禁用，请联系工作人员。 | 码被后台禁用 | 后台解禁或换码 |
| 这个昵称已经被使用，请换一个。 | 昵称重复 | 换个昵称 |
| 该账号已被封禁，请联系工作人员。 | 被封禁 | 找工作人员核实 |
